# V8 Auto-Fetch: Single Entry Point Design

## Principle: No Destruction

V8 currently works. V4b currently works. We are NOT refactoring V4b.
We are NOT changing V8's existing behavior without `-AutoFetch`.
We are extracting V4b's fetch loop into a reusable module function and
giving V8 the OPTION to call it. Every existing workflow continues unchanged.

## New Function: Invoke-SPCachePopulate

### Location
`Modules/SP.Audit/SP.AuditQueries.psm1` -- alongside `Get-SPCachedCampaignItems`

### Purpose
Pure cache population: fetch campaigns from ISC, iterate certifications,
cache items via `Get-SPCachedCampaignItems`. No HTML, no metrics, no
decisions, no scope diff, no state files. Just cache.

### Extracted From
V4b lines 488-564 (Step 1: Campaign Fetch & Audit Build). Only the
fetch+cache loop, not the decision grouping, reviewer metrics, or
snapshot building.

### Signature
```powershell
function Invoke-SPCachePopulate {
    [CmdletBinding()]
    [OutputType([hashtable])]
    param(
        [Parameter()][int]$DaysBack = 18,
        [Parameter()][string]$CampaignName,
        [Parameter()][string]$CampaignNameStartsWith,
        [Parameter()][string]$CampaignNameContains,
        [Parameter()][ValidateSet('STAGED','ACTIVE','COMPLETING','COMPLETED')]
        [string[]]$Status,
        [Parameter()][string]$CorrelationID
    )
```

### Returns
```powershell
@{
    Success       = $true
    CampaignCount = 14
    CertCount     = 2520
    ItemCount     = 28224
    Campaigns     = @($campaignObjects)  # for state tracking to use
    Error         = $null
}
```

### Logic (pseudocode)
```
1. $campaigns = Get-SPAuditCampaigns @filters
2. foreach ($campaign in $campaigns):
   a. $certs = Get-SPAuditCertifications -CampaignId $campaign.id
   b. $items = Get-SPCachedCampaignItems -Campaign $campaign -Certifications $certs
      (this handles cache read/write internally -- if cache valid, returns cached; if not, fetches from ISC)
   c. Accumulate counts
3. Return summary
```

### Key: Get-SPCachedCampaignItems already handles everything
The existing cache function handles:
- Cache hit (return cached data, no ISC call)
- Cache miss (fetch from ISC, write to cache)
- TTL expiry (re-fetch if stale)
- Seal-on-transition (preserve ACTIVE data when campaign completes)
- -NoCache / -RefreshCache modes

So `Invoke-SPCachePopulate` is a thin orchestration wrapper. It does NOT
duplicate cache logic.

### What it does NOT do
- Group decisions (that's Group-SPAuditDecisions)
- Build snapshots (that's Build-SPCampaignSnapshotData)
- Write daily-metrics.jsonl (that's V4b's JSONL writer)
- Write state files (that's Invoke-SPStateTracking)
- Render HTML (that's V4b/V4e/V8)

## V8 Changes

### New Parameters
```powershell
[Parameter()]
[switch]$AutoFetch,

[Parameter()]
[string]$Token,

[Parameter()]
[int]$TokenExpiryMinutes = 10
```

Added to existing `param()` block. Do NOT remove any existing params.

### New Region: Data Pipeline Check

Insert AFTER module load, BEFORE the existing `Read-SPStateFiles` call.
Guard: only runs when `-AutoFetch` is set.

```powershell
#region Data Pipeline Check (opt-in via -AutoFetch)

if ($AutoFetch) {
    # Initialize ISC session if -Token provided
    if (-not [string]::IsNullOrWhiteSpace($Token)) {
        try {
            Set-SPBrowserToken -Token $Token -ExpiryMinutes $TokenExpiryMinutes
            Write-Host '    ISC session initialized from -Token' -ForegroundColor DarkGray
        }
        catch {
            Write-Host "ERROR: Failed to initialize ISC token: $($_.Exception.Message)" -ForegroundColor Red
            exit 4
        }
    }

    # Check if cache has items
    $cacheDir = $null
    try { $cacheDir = Get-SPAuditCacheDir } catch { }
    if ([string]::IsNullOrWhiteSpace($cacheDir)) {
        # Fallback to default
        $cacheDir = Join-Path $toolkitRoot (Join-Path 'Audit' '.cache')
    }
    $cacheFiles = @(Get-ChildItem -Path $cacheDir -Filter 'items-*.jsonl' -File -ErrorAction SilentlyContinue)

    if ($cacheFiles.Count -eq 0) {
        Write-Host '    Cache is empty -- populating from ISC via -AutoFetch...' -ForegroundColor Yellow

        $fetchParams = @{ DaysBack = $DaysBack; CorrelationID = $correlationID }
        if (-not [string]::IsNullOrWhiteSpace($CampaignName))           { $fetchParams['CampaignName'] = $CampaignName }
        if (-not [string]::IsNullOrWhiteSpace($CampaignNameStartsWith)) { $fetchParams['CampaignNameStartsWith'] = $CampaignNameStartsWith }
        if (-not [string]::IsNullOrWhiteSpace($CampaignNameContains))   { $fetchParams['CampaignNameContains'] = $CampaignNameContains }

        $fetchResult = Invoke-SPCachePopulate @fetchParams
        if ($fetchResult.Success) {
            Write-Host "    Cached $($fetchResult.ItemCount) items from $($fetchResult.CampaignCount) campaign(s)" -ForegroundColor Green
        }
        else {
            Write-Host "    ERROR: Cache population failed: $($fetchResult.Error)" -ForegroundColor Red
            Write-Host '    Cannot proceed without cached data.' -ForegroundColor Red
            exit 4
        }
    }
    else {
        Write-Host "    Cache has $($cacheFiles.Count) campaign(s) -- skipping fetch (use -RefreshCache to force)" -ForegroundColor DarkGray
    }
}

#endregion
```

### Enhanced Error Message (No Data, No AutoFetch)

The existing exit-5 path (state files missing, auto-refresh fails, no cache):

```
ERROR: No cached campaign data found.

V8 needs cached items to build state files. To populate the cache:

  Option 1 -- Run V4b first:
    .\Invoke-SPDailyEvidenceReportV4b.ps1 -DaysBack 18 -OutputMode Both

  Option 2 -- Let V8 fetch automatically:
    .\Invoke-SPDailyEvidenceReportV8.ps1 -DaysBack 18 -AutoFetch -Token <token>

  Option 3 -- Use settings.json credentials:
    .\Invoke-SPDailyEvidenceReportV8.ps1 -DaysBack 18 -AutoFetch
    (requires Authentication.ConfigFile or vault configured in settings.json)
```

- All 8+1 HTML sections (unchanged, plus the new 1b privileged section)

## Execution Scenarios

### Scenario A: Normal daily run (no change from today)
```powershell
.\Invoke-SPDailyEvidenceReportV8.ps1 -DaysBack 18
```
- AutoFetch not set → skip cache check entirely
- Read state files → auto-refresh from cache if stale → render report
- **Identical to current behavior**

### Scenario B: Fresh machine, user knows to run V4b first
```powershell
.\Invoke-SPDailyEvidenceReportV4b.ps1 -DaysBack 18 -OutputMode Both
.\Invoke-SPDailyEvidenceReportV8.ps1 -DaysBack 18
```
- V4b populates cache + JSONL
- V8 reads state files, auto-refreshes from cache, renders
- **Identical to current workflow**

### Scenario C: Fresh machine, single command (NEW)
```powershell
.\Invoke-SPDailyEvidenceReportV8.ps1 -DaysBack 18 -AutoFetch -Token $token
```
- AutoFetch set → check cache → empty
- Invoke-SPCachePopulate → fetches from ISC, populates cache
- Read state files → auto-refresh from cache → render report
- **New: one command does everything**

### Scenario D: Cache exists, AutoFetch set (no re-fetch)
```powershell
.\Invoke-SPDailyEvidenceReportV8.ps1 -DaysBack 18 -AutoFetch
```
- AutoFetch set → check cache → has items → skip fetch
- Normal V8 flow
- **Cache is respected, not blindly re-fetched**

### Scenario E: No cache, no AutoFetch (clear error)
```powershell
.\Invoke-SPDailyEvidenceReportV8.ps1 -DaysBack 18
```
- No AutoFetch → skip cache check
- Read state files → missing → auto-refresh from cache → no cache
- Enhanced error message with 3 options
- **Better UX than current "run Update-SPStateFiles.ps1 first"**
