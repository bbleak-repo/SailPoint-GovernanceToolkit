Responsibility Split
MuleSoft -- "What Data"
  • Data extraction from application APIs
  • Business logic and field mapping
  • DataWeave transformation to target schema
  • Error handling and retry logic
  • Writes CSV to staging location
GoAnywhere -- "How to Deliver"
  • Picks up files from staging location
  • Schema validation and row-count checks
  • PGP encryption with SailPoint public key
  • Secure SFTP transfer to SailPoint
  • Audit trail, notifications, and alerting
When to Use
Enterprise environments where MuleSoft already owns integration logic and GoAnywhere owns file transfer infrastructure. Keeps teams separated by ownership: integration team owns data quality, operations team owns secure delivery.
Example Applications
  • Any API-based app in a regulated environment
  • Organizations with a GoAnywhere-first security policy
  • Teams requiring full audit trail on file movement
  • Multi-tenant environments where encryption is mandatory

When to Use

  • Third-party apps where vendor does not provide an API

Pattern Decision Matrix

Answer these questions in order to select the right integration pattern
Decision Table
Question Answer Recommended Pattern
Does your application expose a REST or SOAP API for user and role data? YES Pattern A MuleSoft API Integration
Pattern C MuleSoft + GoAnywhere (if GoAnywhere is standard in your org)
Does your application produce scheduled file exports (CSV, fixed-width, XML)? YES Pattern B GoAnywhere MFT
No API development needed -- GoAnywhere picks up, validates, encrypts, and delivers.
Can you run read-only SQL queries against the application database? YES Pattern D1 MuleSoft Database Connector
Pattern D2 GoAnywhere DB Export Task
None of the above -- no API, no scheduled export, no database access? YES Manual Export Temporary workaround only.
Plan an automation path: engage vendor for API access, request scheduled export, or arrange DB read access.
Does your organization use GoAnywhere as its standard secure file transfer platform? YES Prefer patterns that include GoAnywhere in the delivery leg: Pattern B Pattern C Pattern D2
GoAnywhere provides the audit trail and encryption your security team expects.
Note on multiple matches: If more than one condition is true (for example, your app has both an API and GoAnywhere is available), prefer Pattern C (MuleSoft + GoAnywhere combined) -- MuleSoft handles data quality, GoAnywhere handles secure delivery. This gives you the cleanest separation of concerns and satisfies both integration and security requirements.
Pattern Quick Reference
Pattern A -- MuleSoft API
App has REST/SOAP API. MuleSoft extracts, transforms, and delivers to SailPoint via SFTP. Full automation, no manual steps.
Pattern B -- GoAnywhere MFT
App produces export files. GoAnywhere picks up, validates, encrypts, and delivers. No API required.
Pattern C -- MuleSoft + GoAnywhere
App has API + org uses GoAnywhere. MuleSoft owns data extraction; GoAnywhere owns secure delivery. Best for enterprise environments.
Pattern D -- Database Direct
No API available, but database is accessible via read-only SQL. MuleSoft (D1) or GoAnywhere (D2) queries the DB directly.
