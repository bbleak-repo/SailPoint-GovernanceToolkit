1. Why Your Application Is Being Onboarded

Understanding the business case helps you prioritize this work and design the right integration.

The Governance Requirement

Compliance and audit requirements mandate that all applications with user access are subject to periodic access review. Auditors ask: "Who has access to this system, and has a manager confirmed that access is appropriate?"

Applications that integrate directly with SailPoint (Active Directory, Entra ID, ServiceNow, etc.) are already covered. Your application does not have a native connector -- so we use the SailPoint Delimited File Connector to bring your user and access data into the governance platform via CSV files.

What Happens with Your Data

Once your files are in SailPoint, the system:

  1. Correlates accounts to people -- matches your app's users to corporate identities using email address
  2. Detects changes daily -- compares today's export to yesterday's to identify new accounts, removed accounts, and changed entitlements
  3. Creates certification campaigns -- when changes are detected, each affected user's manager receives a review asking them to confirm the access is appropriate
  4. Generates audit evidence -- produces compliance reports showing who has access, who reviewed it, and what decisions were made
Your role
You provide the data. The IAM team configures SailPoint. Managers review the access. Your ongoing responsibility is to ensure the daily export runs reliably and contains accurate, complete data.

Why This Matters for Your Application

BenefitWhat It Means for You
Audit readinessWhen auditors ask "who has access to [your app]?", the answer is documented, reviewed, and current -- not a scramble to pull reports
Access hygieneTerminated employees, role transfers, and stale accounts are caught daily instead of quarterly
Risk reductionOrphaned accounts and over-provisioned access are surfaced and remediated through the certification process
AccountabilityEvery access decision has a named reviewer, timestamp, and reason -- traceable in case of an incident

2. What Data We Need from You

Two CSV files, delivered daily. Each file is a complete snapshot of your application's current state.

accounts.csv

One row per user account. Contains every current active and disabled account.

Tells SailPoint: "These are the people who have access to my app, and what access they have."

entitlements.csv

One row per role, group, or permission. The catalog of access levels your app offers.

Tells SailPoint: "These are the access levels that exist in my app, and what each one means."

Full export required
Deliver a complete export every day -- every current account and entitlement, not just changes. The governance system detects changes automatically by comparing today's file to yesterday's. Do NOT send only deltas. Do NOT send an empty file when nothing changed.

How the System Detects Changes

DayWhat You SendWhat the System Detects
Day 1500 accountsBaseline -- all 500 treated as initial load
Day 2500 accounts (identical)No changes. No action.
Day 3501 accounts (1 new hire)1 addition. That person's manager gets a certification campaign.
Day 4499 accounts (2 terminated)2 removals. Logged for audit trail.

4. Pattern A: MuleSoft Integration

How to use MuleSoft Anypoint Platform to extract user and entitlement data from your application's API and deliver it to SailPoint.

Architecture Overview

A MuleSoft flow runs on a daily schedule, calls your application's API to retrieve user and role data, transforms the response into the SailPoint CSV format using DataWeave, and writes the files to the SailPoint import location (SFTP or network share).

MuleSoft Flow Components

StepMule ComponentWhat It Does
1. TriggerSchedulerFires daily at 02:00 UTC (configurable). Gives the flow time to complete before the 04:00 UTC SailPoint aggregation window.
2. Fetch accountsHTTP RequestCalls your app's API: GET /api/users (or equivalent). Handles pagination if the API returns paged results.
3. Fetch entitlementsHTTP RequestCalls GET /api/roles or GET /api/groups to retrieve the entitlement catalog.
4. TransformDataWeaveMaps API response fields to the SailPoint CSV columns. Handles multi-valued groups, date formatting, and boolean conversion.
5. Write filesFile Write or SFTP WriteWrites accounts.csv and entitlements.csv to the import path.
6. Error handlingTry/CatchOn failure: logs the error, sends alert to integration team, does NOT write partial files.

DataWeave Transformation Example

Mapping a JSON API response to the SailPoint account CSV format:

%dw 2.0
output application/csv separator=","
---
payload.users map (user) -> {
    id:          user.userId,
    name:        user.username,
    givenName:   user.firstName,
    familyName:  user.lastName,
    "e-mail":    user.email,
    department:  user.department default "",
    groups:      (user.roles joinBy ","),
    IIQDisabled: if (user.status == "active") "false" else "true",
    accountType: user.accountType default "standard",
    created:     user.createdDate,
    lastLogin:   user.lastLoginDate default ""
}
Key DataWeave considerations
  • The e-mail column name contains a hyphen -- wrap it in quotes in DataWeave
  • Multi-valued groups must be joined with commas: user.roles joinBy ","
  • Use default "" for optional fields to avoid null values in the CSV
  • Boolean IIQDisabled must be lowercase string "true" or "false"

What You Need to Provide

  • API documentation -- endpoints, authentication method, response schema
  • API credentials -- service account or API key for the MuleSoft flow
  • Field mapping -- which API fields correspond to each CSV column (the IAM team will help)
  • Pagination details -- how your API handles large result sets
  • Rate limits -- if your API has request limits, the MuleSoft flow needs to respect them
Who builds the MuleSoft flow?
The integration team builds and maintains the MuleSoft flow. You provide the API access and field mapping. You do not need MuleSoft expertise.

5. Pattern B: GoAnywhere Managed File Transfer

How to use GoAnywhere MFT to securely transfer your application's export files to SailPoint.

Architecture Overview

Your application produces export files on a schedule (or you trigger an export manually). GoAnywhere picks up the files, validates them against the expected schema, optionally encrypts them with PGP, and delivers them to the SailPoint import location via SFTP.

GoAnywhere Project Steps

StepGoAnywhere TaskWhat It Does
1. TriggerSchedule or File MonitorSchedule: fires daily at a set time. File Monitor: triggers when a new file appears in the source directory.
2. Pick up filesRead File or SFTP GetRetrieves accounts.csv and entitlements.csv from the source location (network share, SFTP, local path).
3. ValidateRow Count CheckVerifies the file is not empty and has a reasonable row count (protects against truncated exports).
4. Schema checkCSV Parse + ValidateConfirms required columns are present, encoding is UTF-8, delimiter is comma.
5. TransformCSV Translate (if needed)Renames columns, changes delimiters, adjusts encoding if your app's native export does not match the SailPoint format.
6. EncryptPGP EncryptEncrypts files using the SailPoint import PGP public key (if required by security policy).
7. TransferSFTP PutDelivers files to sftp://[SFTP-HOST]/imports/[AppName]/
8. NotifySend EmailSends confirmation to the app team and IAM team. On failure, sends alert with error details.
9. ArchiveMove/RenameMoves processed source files to an archive directory with date-stamped names for audit trail.

GoAnywhere Configuration Highlights

File Monitor Trigger (recommended over schedule)

Instead of running on a fixed schedule, configure GoAnywhere to watch a directory for new files. When your app drops a new export, GoAnywhere automatically picks it up and processes it. This decouples your export schedule from the transfer schedule.

Row Count Threshold

Set a minimum row count check (e.g., "file must have at least 80% of yesterday's row count"). This prevents a truncated or corrupted export from being delivered to SailPoint, which would look like a mass account deletion.

PGP Encryption

If your security policy requires encryption in transit beyond SFTP:

  • The IAM team provides a PGP public key for encryption
  • GoAnywhere encrypts before SFTP transfer
  • SailPoint's Virtual Appliance (VA) decrypts on receipt using the corresponding private key

What You Need to Provide

  • Source file location -- where your app drops its export files (network path, SFTP, local)
  • Export schedule -- when your app produces the files (time, timezone, frequency)
  • File naming convention -- how the files are named (e.g., users_YYYYMMDD.csv)
  • Expected row count range -- approximate number of accounts (for threshold validation)
  • Source file format -- if your export does not match the SailPoint CSV format, document the differences so GoAnywhere can transform
Who configures GoAnywhere?
The integration team or your MFT administrator configures the GoAnywhere project. You provide the source location, schedule, and file format details. You do not need GoAnywhere expertise.

6. Pattern C: MuleSoft + GoAnywhere Combined

When your organization uses both platforms, each handles what it does best: MuleSoft for data extraction and transformation, GoAnywhere for secure file delivery.

Why Combine?

MuleSoft Handles

  • API integration (HTTP, SOAP, JDBC)
  • Business logic and field mapping
  • DataWeave transformation to CSV
  • Error handling and retry
  • Drops files to a staging location

GoAnywhere Handles

  • File pickup from staging
  • Schema and row count validation
  • PGP encryption (if required)
  • SFTP delivery to SailPoint
  • Audit trail and notifications

When This Makes Sense

  • Your organization has established MuleSoft as the API integration platform
  • Your organization has established GoAnywhere as the managed file transfer platform
  • Security policy requires PGP encryption or audit-grade file transfer logging that GoAnywhere provides natively
  • The integration team wants to separate concerns: MuleSoft team owns "what data," MFT team owns "how to deliver"

Staging Location

MuleSoft writes files to a shared staging location (network share or SFTP directory). GoAnywhere monitors this location and picks up files automatically.

ComponentStaging PathDirection
MuleSoft writes to\\staging\sailpoint\[AppName]\outbound\Output
GoAnywhere reads from\\staging\sailpoint\[AppName]\outbound\Input
GoAnywhere delivers tosftp://[SFTP-HOST]/imports/[AppName]/Output
Timing
MuleSoft should complete its extraction by 01:30 UTC. GoAnywhere picks up and delivers by 03:00 UTC. SailPoint aggregation runs at 04:00 UTC. Build in buffer time for retries.

8. Validation and Testing

Validate your files before going live. The toolkit provides automated validation that checks everything.

Self-Service Validation

Run this command to validate your files before requesting production activation:

.\Scripts\Invoke-SPDisconnectedAppRegistry.ps1 -Action Test -AppName "YourAppName"

The validator checks:

CheckWhat It Validates
Required columnsAll required columns present with exact names (case-sensitive)
EncodingFile is UTF-8 (not UTF-16 or ANSI)
Duplicate IDsNo duplicate account IDs in the account file
Email formatEmail addresses are syntactically valid
Cross-referenceEvery group value in the account file has a matching ID in the entitlement file
Field lengthsNo field exceeds maximum length
Boolean formatIIQDisabled contains only true or false (not yes/no, 0/1)
Row countFile is not empty and has a reasonable number of rows
Common validation failures
  • Excel UTF-16: Excel's default "CSV" format is UTF-16, not UTF-8. Use "CSV UTF-8" in Save As.
  • Column name case: Email is not the same as e-mail. Match exactly.
  • Commas in IDs: APP,ADMIN breaks CSV parsing. Use APP-ADMIN.
  • IIQDisabled as yes/no: Must be literal true or false.

Integration Testing Checklist

Before going live, work through this with the IAM team:

  1. Produce a test export from your application (real data or sanitized sample)
  2. Run the self-service validator -- fix any errors
  3. Deliver test files via your chosen integration pattern (MuleSoft/GoAnywhere/direct)
  4. IAM team imports into SailPoint sandbox and verifies: accounts correlate to identities, entitlements display correctly, changes are detected between day 1 and day 2 exports
  5. Run a test certification campaign in sandbox -- verify reviewers see the right data
  6. Go live with production data delivery
