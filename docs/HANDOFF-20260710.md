### 2. V4b / V4 genuine reviewer sign-off
**Bug (user-reported):** force-closed campaigns showed "Closed with incomplete work —
100 of 100 reviewers signed off, X items never manually decided" while the same
report's accountability section listed 17+ reviewers with undecided items. Also the
header said 100 while the Reviewers row said 110 (mixed distinct-vs-entries bases).

**Root cause:** sign-off came from cert `Phase=='SIGNED'` (ISC force-signs every cert
at close). The existing correction (`Get-SPForceSignedReviewerCount`) needs positive
`signedBy.id != reviewer.id` evidence, which production rosters didn't carry → inert.
It was also COUNT arithmetic, which can double-subtract.

**Fix:** new pure helper **`Get-SPGenuineReviewerSignOff`** (SP.AuditReportCore,
exported) computes with SETS over distinct reviewer keys:
`genuineSigned = signed − forceSignEvidence − reviewersWithUndecidedItems`
(a reviewer holding canonically-undecided items cannot have genuinely signed — the
pending veto works even with zero signedBy provenance). Returns Signed / Total /
SignedRaw / AutoClosed / NotStarted / GenuineSignedNames.

Wired into:
- **V4b exec box** ("83 of 100 Reviewers Signed Off"), Key Indicators, Section A
  "Reviewer %", and the closed-incomplete caption which now appends
  "(N reviewer(s) auto-closed at force-close)".
- **V4b JSONL writer** (`daily-metrics.jsonl`): `reviewersSigned` is now GENUINE,
  `reviewersTotal` is DISTINCT-by-reviewer; new fields `reviewersSignedRaw`,
  `reviewersAutoClosed`, `reviewerEntries` (the old per-cert entry count);
  per-reviewer `signed` flag is genuine too. **`schemaVersion` bumped to 3**
  (3 = 2 + genuine sign-off semantics; V7's suspect gate checks >=2, unaffected).
- **V4 script**: same exec box + Section A changes (no JSONL there).
- Exec "Reviewers" row now reads
  `"<distinct> distinct (<entries> entries: N primary, M reassigned)"` so the
  distinct sign-off denominator and the entries breakdown can't be confused again.
- V4e/V4f were already pending-aware via `Get-SPSeriesInstanceCompletion` — they agree
  with the new numbers by construction.
- Tests: `Tests/SP.GenuineReviewerSignOff.Tests.ps1` (GSO-01..05, incl. the
  no-provenance production shape and the both-signals-subtract-once case).

### 3. V4e hang at "Step 3: compute series attestation delta" (3 h, ~1 core busy)
**Root cause — quadratic hot path, not a loop bug:** `Resolve-SPSeriesItemState`
rebuilt the roster→cert index **per item**, making the engine O(items × roster) with
two nested CmdletBinding calls per roster entry; V4e then re-resolved every item a
second time for per-instance completion. At 13 instances × thousands of items × a
large roster that's tens of millions of PowerShell function invocations → hours.

**Fixes (SP.CampaignSeries.psm1):**
- `New-SPSeriesRosterIndex` — the CertId→entry index is built ONCE per instance and
  threaded via new `-RosterIndex` param (old per-call build kept for direct callers).
- Hot loops (per-key timeline walk, per-instance dedupe, facts extractor, resolve
  reads) converted to direct member access — safe because the module runs
  StrictMode 1 (missing member reads `$null` on both hashtable and PSCustomObject).
- New optional `-ProgressCallback` on `Get-SPSeriesAttestationDelta`; V4e/V4f print
  per-instance load + resolve progress and per-series elapsed, so a long run is never
  silent again.

**Measured (synthetic, same fixture both builds):**
| Scale | Old | New |
|---|---|---|
| 500 items × 4 inst × 100 certs (delta) | 54.5 s | 6.5 s |
| completion, 1 instance × 500 items | 12.4 s | 1.4 s |
| 2,000 items × 13 inst × 150 certs (delta) | (hours-class) | **57 s** |

Output equivalence old-vs-new verified on identical fixtures (same counts/signed).
Bench scripts live in the session scratchpad only (not committed).

**Step 2 mystery:** it only printed when `-SimilarityThreshold > 0`. Both V4e and V4f
now print "Step 2 ... skipped (off by default)" so the numbering always reads 1→2→3.
