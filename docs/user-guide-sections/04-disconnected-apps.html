Disconnected Apps

Disconnected App Onboarding provides certification governance for applications that lack native ISC connectors. App teams export daily account and entitlement CSV files to a shared location; the toolkit validates the files, detects day-over-day access changes, resolves identities to ISC records, and creates targeted manager-routed certification campaigns -- the same pattern used by Delta Certification, adapted for flat-file sources. A registry tracks all onboarded apps, and a batch orchestrator processes them in sequence with SLA monitoring, team dashboards, and cross-app analytics.

Disconnected App Overview

Many enterprise applications -- legacy mainframe systems, vendor-hosted SaaS platforms, niche financial tools -- have no SailPoint ISC connector and no public API. The only viable integration path is flat-file import: the app team extracts a CSV of current accounts and entitlements, places it on a shared drive or SFTP location, and the toolkit picks it up for governance.

Why Flat Files?

  • No connector available -- ISC has ~200 connectors, but thousands of enterprise apps fall outside that catalog (e.g., PEP+ by Fiserv, DebtNext dPlat, IPAY by Jack Henry).
  • No admin API -- even SaaS apps may not expose a REST API for reading account/entitlement data.
  • Compliance deadline -- building a custom connector takes weeks to months; flat-file onboarding can begin the same day.
  • Phase 1 / Phase 2 pattern -- start with flat-file CSV governance (Phase 1), then invest in a custom connector only if the app's user volume and churn rate justify it (Phase 2).

CSV Templates

Two CSV files define each disconnected app's identity data: an accounts file (who has access) and an optional entitlements file (what access exists). The toolkit validates both files against a strict schema before processing.

Account CSV Columns

Column Required Description
id Yes Unique account identifier. Max 128 characters. No duplicates allowed.
name Yes Account display name or username.
givenName Yes First name of the account holder.
familyName Yes Last name of the account holder.
e-mail Yes Email address. Must contain @. Primary correlation attribute for ISC identity resolution.
department No Organizational department. Included in reports but not used for correlation.
groups Yes Comma-separated entitlement IDs. Must match id values in the entitlement file. Drives delta detection for entitlement grants and revocations.
IIQDisabled Yes Account status: true (disabled) or false (active). Drives enable/disable delta detection.
accountType No (v2) Account classification (e.g., Standard, Admin, Service). v2 extension.
created No (v2) Account creation date. v2 extension.
lastLogin No (v2) Last authentication timestamp. v2 extension.

Entitlement CSV Columns

Column Required Description
id Yes Unique entitlement identifier. Referenced by the groups column in the account file.
name Yes Entitlement name. No + characters or emoji allowed.
displayName Yes Human-readable label shown in ISC and reports.
description Yes What this entitlement grants. Max 2,000 characters.
owner No (v2) Entitlement owner email or name. v2 extension.
type No (v2) Entitlement type classification (e.g., Role, Permission, Group). v2 extension.
riskLevel No (v2) Risk level (e.g., Low, Medium, High, Critical). v2 extension.

Cross-Reference Validation

Test-SPDisconnectedAppCrossReference verifies referential integrity between the two files. Every entitlement ID in an account's groups column must exist in the entitlement file's id column. Orphaned entitlements (defined but never referenced) are reported as warnings.

Example Account CSV

ACC-001,jsmith,John,Smith,john.smith@contoso.com,Finance,"ENT-VIEWER,ENT-APPROVER",false
ACC-002,jdoe,Jane,Doe,jane.doe@contoso.com,IT,"ENT-ADMIN",false
ACC-003,svc-batch,Service,Account,svc-batch@contoso.com,IT,"ENT-ADMIN,ENT-VIEWER",true

Example Entitlement CSV

id,name,displayName,description
ENT-VIEWER,Viewer,Read-Only Viewer,View reports and dashboards without modification access
ENT-APPROVER,Approver,Transaction Approver,Approve financial transactions up to $10000
ENT-ADMIN,Administrator,Full Administrator,Full administrative access including user management

Onboarding a New App

Invoke-SPDisconnectedAppRegistry.ps1 manages the app registry in Config/settings.json. Four actions are available: Register, Unregister, List, and Test.

Step 1: Prepare CSV Files

Copy the templates from Config/Templates/v2/ and populate them with real data from the target application. Place the files on a shared drive or local path accessible to the toolkit.

# Copy templates
Copy-Item Config\Templates\v2\disconnected-app-accounts.csv \\fileserver\imports\MyApp\accounts.csv
Copy-Item Config\Templates\v2\disconnected-app-entitlements.csv \\fileserver\imports\MyApp\entitlements.csv

# Populate with real data (use your app team's export process)

Step 2: Register the App

.\Scripts\Invoke-SPDisconnectedAppRegistry.ps1 -Action Register `
    -AppName "MyApp" `
    -AccountFilePath "\\fileserver\imports\MyApp\accounts.csv" `
    -EntitlementFilePath "\\fileserver\imports\MyApp\entitlements.csv" `
    -CorrelationAttribute "e-mail" `
    -CampaignNamePrefix "MyApp Cert" `
    -DeadlineDays 2 `
    -SlaDays 1

This adds an entry to DisconnectedApps.Applications in settings.json and creates the directory structure (Imports, Snapshots, Reports under the app name).

Step 3: Validate the Files

# Run 5-step validation: file paths, CSV structure, entitlements, cross-references
.\Scripts\Invoke-SPDisconnectedAppRegistry.ps1 -Action Test -AppName "MyApp"

The Test action runs five validation checks:

  1. Account file path exists and is readable
  2. Account CSV structure: required columns present, no empty IDs, no duplicate IDs, id length <= 128, IIQDisabled is true or false, e-mail contains @
  3. Entitlement file path exists (if configured)
  4. Entitlement CSV structure: required columns, no duplicate IDs, description <= 2,000 chars, no + in name
  5. Cross-reference: all groups values in accounts resolve to entitlement IDs

Step 4: List Registered Apps

# View all registered apps with delivery status
.\Scripts\Invoke-SPDisconnectedAppRegistry.ps1 -Action List

Output shows Name, Enabled, FileStatus (Current / Stale / Missing / Empty / Error), LastProcessed (from snapshot filename), and AccountPath.

Single App Processing

Invoke-SPDisconnectedAppCert.ps1 runs the full daily certification pipeline for a single app: validate, snapshot, detect deltas, resolve identities, create campaigns, and generate reports.

Pipeline Steps

  1. Validate -- Test-SPDisconnectedAppAccountFile checks CSV structure and data integrity. If an entitlement file is provided, Test-SPDisconnectedAppEntitlementFile and Test-SPDisconnectedAppCrossReference also run.
  2. Snapshot -- Save-SPDisconnectedAppSnapshot copies the current CSV to {SnapshotDir}/{AppName}/{YYYY-MM-DD}-accounts.csv. Idempotent: re-running on the same day does not create duplicate snapshots.
  3. Previous Snapshot -- Get-SPDisconnectedAppPreviousSnapshot finds the most recent snapshot before today. Returns $null on first run.
  4. Delta Detection -- Compare-SPDisconnectedAppFiles compares today's file against yesterday's snapshot. Seven change types detected (see Delta Detection below).
  5. Threshold Check -- Test-SPDisconnectedAppDeletionThreshold blocks processing if account removals exceed AccountDeletionThresholdPct (default: 20%). Prevents mass-revocation from corrupt or truncated CSV files.
  6. Identity Resolution -- Resolve-SPDisconnectedAppIdentities resolves changed accounts to ISC identities via POST /v3/search (email primary, username fallback). Session-level cache avoids duplicate API calls.
  7. Campaign Creation -- Invoke-SPDisconnectedAppCertRun groups resolved identities by manager and creates one SEARCH campaign per manager. Includes duplicate campaign detection and MaxCampaignsPerRun safety guard (default: 20).
  8. HTML Report -- Export-SPDisconnectedAppDeltaHtml generates a self-contained delta report with six sections.
  9. Audit Event -- JSONL audit trail entry appended for compliance evidence.

Batch Processing

Invoke-SPDisconnectedAppBatch.ps1 processes all registered apps (or a specified subset) in a single coordinated run. Designed for enterprises with 20+ disconnected apps that need daily governance.

Batch Pipeline

The batch orchestrator runs three phases:

Phase Step Operation
Pre 1 Campaign cleanup -- complete past-due campaigns (requires Safety.AllowCompleteCampaign = true)
2 Load registered apps from settings.json (filter to enabled, or -AppNames subset)
Per-App 3 CSV validation (structure + cross-reference)
4 Snapshot today's file
5 ISC source upload (if ISCSourceId configured)
6 Find previous snapshot + delta detection
7 Deletion threshold check
8 Identity resolution + manager grouping + campaign creation
9 Per-app HTML delta report
Post 10 Batch summary HTML report
11 Escalation -- reassign stale certifications across all apps
12 Team dashboards -- regenerate per-app status pages

Each app is processed independently -- a failure in one app does not prevent subsequent apps from running. The batch summary report aggregates all results with color-coded per-app status.

Delta Detection

Compare-SPDisconnectedAppFiles compares today's account CSV against yesterday's snapshot and classifies every account into one of seven change types. The comparison uses O(1) hashtable lookups keyed by the id column for performance.

Change Types

Change Type Detection Logic Triggers Campaign?
AccountAdded Account ID exists in today's file but not in yesterday's snapshot. Yes
AccountRemoved Account ID exists in yesterday's snapshot but not in today's file. No (informational)
AccountDisabled IIQDisabled changed from false to true. No (informational)
AccountEnabled IIQDisabled changed from true to false. Yes
EntitlementGranted New entitlement ID(s) appear in the groups column compared to yesterday. Yes
EntitlementRevoked Entitlement ID(s) removed from the groups column compared to yesterday. No (informational)
AttributeChanged Any other column value differs between today and yesterday (e.g., name, email, department). No (informational)

Only three change types trigger certification campaigns: AccountAdded, AccountEnabled, and EntitlementGranted. These represent new or expanded access that requires manager review. Removals, disables, and attribute changes are captured in the delta report for audit visibility but do not create campaigns.

First Run Behavior

On the first run for an app (no previous snapshot exists), all accounts in the CSV are treated as AccountAdded. This creates campaigns for every identity in the file, establishing the baseline. Subsequent runs detect only day-over-day changes.

Deletion Threshold Protection

Test-SPDisconnectedAppDeletionThreshold prevents mass-revocation from corrupt or truncated CSV files. If the percentage of removed accounts exceeds AccountDeletionThresholdPct (default: 20%), processing is blocked.

Scenario Behavior
First run (no previous snapshot) Threshold check bypassed -- all accounts are Added.
Previous snapshot has < 5 accounts Threshold check bypassed -- too few accounts for meaningful percentage.
Removals <= 20% of previous count Processing continues normally.
Removals > 20% of previous count Processing blocked. Exit code 5. Investigate the CSV before re-running.
Threshold exceeded? Verify that the CSV file is complete and not truncated. If the removals are legitimate (e.g., a department was offboarded), increase DisconnectedApps.AccountDeletionThresholdPct temporarily, re-run, then restore the default.

Remediation Tracking

When a reviewer revokes an entitlement in an ISC certification campaign, that decision must be verified against the next day's CSV to confirm the app team actually removed the access. The remediation tracking workflow bridges this gap between ISC governance decisions and real-world access removal.

How It Works

  1. Decision harvest -- Get-SPDisconnectedAppCampaignDecisions queries completed campaigns and collects revocation decisions (see Decision Collection below).
  2. Record creation -- New-SPRemediationRecord writes revocation details to remediation-tracker.json in the app's report directory. Each record includes: identity, entitlement, campaign ID, decision timestamp, and status (Pending).
  3. Verification -- On the next daily run, delta detection identifies EntitlementRevoked changes. The toolkit cross-references these against pending remediation records to confirm removal.
  4. Status update -- Confirmed removals are marked Remediated with the verification date. Unconfirmed removals remain Pending and are flagged in the team dashboard and batch summary.

Remediation States

State Description
Pending Revocation decision made in ISC but not yet confirmed in next-day CSV.
Remediated Entitlement removal confirmed: the group no longer appears in the account's groups column.
Overdue More than DeadlineDays elapsed since the revocation decision with no confirmation.
No provisioning API: Disconnected apps by definition lack an API for automated access removal. The revocation decision in ISC is a directive to the app team, not an automated action. Remediation tracking provides accountability evidence that the directive was fulfilled.

Decision Collection

Get-SPDisconnectedAppCampaignDecisions harvests certification outcomes from completed ISC campaigns, providing the raw data for remediation tracking and compliance reporting.

How It Works

  1. Reads the JSONL audit trail for campaign IDs created within the last DaysBack days (default: 7).
  2. Queries ISC for each campaign's current status via Get-SPCampaign.
  3. For completed campaigns, retrieves item-level decisions via Get-SPAuditCertifications and Get-SPAuditCertificationItems.
  4. Classifies decisions: Approved, Revoked, or Pending.

Parameters

-AppName string (required) Application name. Used to locate audit trail and filter campaigns by prefix.
-DaysBack int 7 Look-back window for campaign IDs in the audit trail. Range: 1-365.
-OutputPath string .\DisconnectedApps\Reports Directory containing the JSONL audit trail.

Cross-App Analytics

Two functions provide enterprise-wide visibility across all registered disconnected apps.

Identity Risk Analysis

Get-SPDisconnectedAppIdentityRisk reads the latest account snapshot from each registered app and builds a cross-app identity map keyed by email address. No ISC API calls are made -- this is a purely local analysis.

Risk Level Condition Example
Normal Identity appears in 1 app John Smith has a PEP+ account only
Elevated Identity appears in 2 apps Jane Doe has both PEP+ and DebtNext accounts
High Identity appears in 3+ apps Service account svc-batch has accounts in PEP+, DebtNext, and IPAY

Export-SPDisconnectedAppIdentityRiskHtml generates a risk report with an executive summary (total identities, single-app, multi-app, high-risk counts) and a color-coded identity table. For large environments (over 500 identities), the all-identity table is suppressed and only multi-app identities are shown.

Entitlement Catalog

Get-SPDisconnectedAppEntitlementCatalog reads the latest entitlement snapshot from all registered apps and produces a unified catalog. This provides a single view of all entitlements across all disconnected apps.

Export-SPDisconnectedAppEntitlementCatalogHtml generates the catalog as a searchable HTML report, organized by app with entitlement details including name, display name, description, and v2 extensions (owner, type, risk level) when available.

Examples

# Identity risk analysis
$risk = Get-SPDisconnectedAppIdentityRisk
Export-SPDisconnectedAppIdentityRiskHtml -RiskResult $risk.Data
Write-Host "High-risk identities: $($risk.Data.Summary.HighRisk)"

# Entitlement catalog
$catalog = Get-SPDisconnectedAppEntitlementCatalog
Export-SPDisconnectedAppEntitlementCatalogHtml -CatalogResult $catalog.Data

Campaign Cleanup and Escalation

The disconnected apps module reuses the same cleanup and escalation patterns as Delta Certification, adapted for per-app campaign prefixes.

Campaign Cleanup

Invoke-SPDisconnectedAppCleanup finds active campaigns matching each app's CampaignNamePrefix and completes past-due campaigns older than DaysStale (default: 3 days).

Parameter Type Default Description
-AppNames string[] all registered apps Limit cleanup to specific apps.
-DaysStale int 3 Days before a campaign is eligible for auto-completion.
-WhatIf switch off Preview which campaigns would be completed.
Safety Guard: Cleanup is guarded by Safety.AllowCompleteCampaign (default: false). Set to true in settings.json for cleanup to make API calls. This is the same guard used by Delta Certification cleanup.

Escalation

Invoke-SPDisconnectedAppEscalation detects stale certifications across all registered apps and escalates them via org-tree reassignment. Each app can override the default stale-hours threshold via its EscalationStaleHours setting.

Parameter Type Default Description
-AppNames string[] all registered apps Limit escalation to specific apps.
-DefaultStaleHours int 24 Hours without reviewer action before escalation. Per-app EscalationStaleHours overrides this.
-MaxEscalationLevels int 2 Maximum org-tree hops from the original reviewer.
-WhatIf switch off Preview which certifications would be escalated.

ISC Source Upload

Push-SPDisconnectedAppToISC optionally uploads the account and entitlement CSV files to an ISC delimited file source for aggregation. This enables ISC to display the disconnected app's accounts alongside native connector sources in the identity cube.

Upload Methods

Method How It Works When to Use
API Multipart/form-data POST to the ISC source import endpoint. Direct API access available (no firewall restrictions).
FileDrop Copies CSV files to a configured file drop path monitored by the Virtual Appliance. Network restrictions prevent direct API access; VA handles the upload.

Configuration

ISC upload is optional and controlled per-app. Set ISCSourceId in the app registration to enable upload. Leave it empty to skip.

"ISC": {
    "UploadMethod": "API",              // "API" or "FileDrop"

Per-App Settings

Setting Type Description
Name string Unique application name. Used for directory paths, campaign naming, and report organization.
AccountFilePath string Path to the daily account CSV. UNC paths supported for shared drives.
EntitlementFilePath string Path to the entitlement CSV. Empty string to skip entitlement validation.
ISCSourceId string ISC source ID for CSV upload. Empty string to skip upload.
CorrelationAttribute string Identity attribute for ISC search resolution. Default: e-mail.
CampaignNamePrefix string Prefix for campaign names. Full name: {Prefix} {YYYY-MM-DD} - {ManagerName}.
DeadlineDays int Campaign deadline in days from creation.
SlaDays int Expected delivery frequency. SLA compliance checks use this value.
Enabled bool Whether the batch orchestrator includes this app. Disabled apps are skipped.
