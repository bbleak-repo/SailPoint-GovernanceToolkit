Delta Certification

Delta Certification detects daily AD access changes by querying SailPoint ISC account-activity events for GRANT_ACCESS operations. When new grants are found, the toolkit creates targeted certification campaigns scoped to only the identities who received new access, routed to their managers (or source owners) for review. Combined with escalation, cleanup, and reporting scripts, this forms a continuous compliance loop for AD entitlement governance.

Delta Cert Overview

The delta certification workflow addresses a gap in ISC's native certification capabilities: there is no built-in way to automatically certify only new access grants on a daily basis. Standard ISC campaigns review all entitlements for a population, which is too broad for day-to-day change detection. The toolkit fills this gap with an event-driven approach.

How It Works

  1. Event Detection -- Get-SPDeltaGrantEvents queries GET /v3/account-activities for GRANT_ACCESS events on specified AD source IDs within a configurable time window (default: 24 hours).
  2. Identity Resolution -- Get-SPDeltaAffectedIdentities resolves each event to an active ISC identity, filtering out terminated, inactive, leaver, and prehire lifecycle states. Additional exclusion filters (display name patterns, explicit identity IDs) are configurable.
  3. Manager Grouping -- Group-SPDeltaByManager groups affected identities by their ISC manager, forming one reviewer group per manager.
  4. Campaign Creation -- Invoke-SPDeltaCertRun creates one SEARCH-type certification campaign per manager group, scoped via identity ID filter (id:"abc" OR id:"def"). Each campaign is started immediately after creation.

Campaign naming convention: {Prefix} {YYYY-MM-DD} - {ManagerName}

Scope Requirement

Important: GET /v3/account-activities requires sp:scopes:all -- there is no granular scope for this endpoint. Use a browser token (-Token) from the ISC admin console as a workaround, or configure a PAT with sp:scopes:all.

Output Structure

DeltaCert\
    deltacert-audit.jsonl          # Append-only JSONL audit trail (one line per run)
    deltacert-escalation.jsonl     # Escalation event log
    reports\

        delta-report-YYYY-MM-DD.jsonl  # Machine-readable report data

The primary delta certification script. Creates daily campaigns for managers of identities who received new AD access.

    [-CampaignNamePrefix <string>] [-MaxCampaignsPerRun <int>]
    [-ReviewerMode <string>] [-RunCleanup]
    [-ConfigPath <string>] [-Token <string>] [-TokenExpiryMinutes <int>]
    [-OutputMode <string>] [-WhatIf] [-Help]

Required Parameters

Parameter Type Description
-SourceId string[] One or more SailPoint ISC source IDs to monitor for AD group add operations. Obtain from: ISC Admin > Sources > select source > URL contains the source ID. Example: -SourceId 'abc123def456' or @('src-1','src-2')

Campaign Parameters

Parameter Type Default Description
-HoursBack int 24 Look-back window in hours. Increase to 48+ for catch-up after a missed run.
-DeadlineDays int 2 Days from today until the campaign deadline. ISC enforces this deadline on the campaign.
-FallbackReviewerIdentityId string -- Identity ID of the reviewer for identities with no manager in ISC. If omitted, manager-less identities are skipped with warnings.

-MaxCampaignsPerRun int 50 Safety guard -- abort before creating any campaigns if the number of manager groups exceeds this threshold. Also configurable via DeltaCert.MaxCampaignsPerRun.
-ReviewerMode string Manager Who reviews the campaigns. Manager: one SEARCH campaign per manager group. SourceOwner: one SOURCE_OWNER campaign per source ID. See Reviewer Modes below.
-RunCleanup switch off Run Invoke-SPDeltaCertCleanup before creating new campaigns. Completes past-due campaigns older than DeltaCert.CleanupDaysStale (default: 3 days). Requires Safety.AllowCompleteCampaign = true.

-TokenExpiryMinutes int 10 Minutes until the browser token is considered expired. ISC browser tokens are typically valid for ~12 minutes.
-ConfigPath string ..\Config\settings.json Path to settings.json.

Output Parameters

Parameter Type Default Description
-OutputMode string Console Console summary format. Valid values: Console, JSON, Both.
-WhatIf switch off Dry-run mode. Shows what campaigns would be created without making any write API calls.
-Help switch off Display full comment-based help and exit.

Reviewer Modes

The -ReviewerMode parameter (or DeltaCert.DefaultReviewerMode in settings.json) controls how certification campaigns are routed to reviewers.

Mode Campaign Type Grouping Best For
Manager (default) SEARCH One campaign per manager group. Each manager reviews only their direct reports who received new AD access. Organizations where managers are accountable for their team's access.
SourceOwner SOURCE_OWNER One campaign per AD source ID. ISC automatically routes certification items to whoever owns each source. Organizations where application/source owners control access decisions. Fewer API calls (skips identity resolution and manager grouping).

Manager Mode Flow

Get-SPDeltaGrantEvents (GRANT_ACCESS events)
  -> Get-SPDeltaAffectedIdentities (resolve to active identities)
    -> Group-SPDeltaByManager (one group per manager)
      -> For each manager:
           New-SPCampaign -Type SEARCH -SearchFilter 'id:"x" OR id:"y"' -CertifierIdentityId $managerId
           Start-SPCampaign

SourceOwner Mode Flow

Get-SPDeltaGrantEvents (GRANT_ACCESS events)
  -> For each unique SourceId:
       New-SPCampaign -Type SOURCE_OWNER -SourceId $sourceId
       Start-SPCampaign

Campaign Cleanup

Over time, managers may neglect to act on their delta cert campaigns, causing campaign pile-up. Invoke-SPDeltaCertCleanup finds past-due delta cert campaigns and completes them, preventing stale campaigns from accumulating.

How Cleanup Works

  1. Searches for active campaigns matching the campaign name prefix via Search-SPCampaigns -Keyword $Prefix -Status @('ACTIVE')
  2. For each campaign, checks if the deadline has passed or if the campaign is older than CleanupDaysStale (default: 3 days)
  3. Calls Complete-SPCampaign -CampaignId $id on past-due campaigns
  4. Returns a summary: campaigns completed, campaigns still active, errors
Safety Guard: Complete-SPCampaign is guarded by Safety.AllowCompleteCampaign (default: false). You must set this to true in settings.json for cleanup to work. When blocked, the function returns Success=$false with a clear error message and makes no API calls.

Triggering Cleanup

Cleanup runs when you pass -RunCleanup to Invoke-SPADDeltaCert.ps1. It executes before creating new campaigns. Example:

# Run cleanup then create new campaigns
.\Scripts\Invoke-SPADDeltaCert.ps1 -SourceId 'src-abc123' -RunCleanup -Token $token

Configuration

Setting Default Description
DeltaCert.CleanupDaysStale 3 Days before an active delta cert campaign is considered stale and eligible for completion.
Safety.AllowCompleteCampaign false Must be true for cleanup to call the ISC campaign-complete API.

Escalation

When a reviewer does not act on a certification within a configurable threshold, the toolkit can escalate by reassigning the certification to the reviewer's manager in the ISC org tree.

Escalation Workflow

  1. Stale Detection -- Get-SPDeltaCertStaleCertifications finds active delta cert certifications where signed is null (not completed) and created is older than StaleHours (default: 24).
  2. Org Tree Walk -- Invoke-SPDeltaCertEscalate looks up each stale reviewer's manager via Get-SPDeltaIdentityDetail.
  3. Reassignment -- Calls Invoke-SPReassign to reassign the certification to the reviewer's manager. The reassignment reason includes the hours-open context: "SLA escalation: 48 hours without action".
  4. ISC Notification -- ISC sends its own email notification to the new reviewer when a certification is reassigned. No custom email logic is needed.

Escalation Safeguards

Safeguard Behavior
No manager Reviewer with no manager in ISC is skipped with a WARN log (not an error).
Max escalation levels MaxEscalationLevels (default: 2) prevents infinite escalation loops. If the reviewer's manager was already the target from a previous escalation, the walk goes up one more level.
Large certifications Certifications with >50 review items automatically use Invoke-SPReassignAsync (max 500 items) instead of the synchronous endpoint (max 50).
Governance Groups Reassignment does NOT work for Governance Group certifications (documented ISC exception). These are detected and skipped with a WARN log.

Delta Reports

Invoke-SPDeltaReport.ps1 generates a lightweight daily operations report showing what changed since the last run. This is not a full campaign audit -- it shows only access changes within the time window for quick daily review.

Report Contents

Section Data Source Purpose
New Grants GRANT_ACCESS account-activity events Identities that received new AD group memberships
Revocations REVOKE_ACCESS account-activity events AD group memberships that were removed
Campaigns Created Delta cert campaign search New campaigns created in this period
Pending Reviews Active certification items Items awaiting reviewer action
Anomalies Cross-reference analysis Unusual patterns (e.g., grants immediately followed by revocations)

Scheduling

The delta certification scripts are designed to run unattended on a schedule. The recommended setup uses Windows Task Scheduler for on-premise environments or cron for Linux/macOS.

Recommended Schedule

Script Schedule Purpose
Invoke-SPDailyOrchestrator.ps1 Daily at 06:00 Full daily workflow: cleanup, delta cert, report, escalation, health check
Invoke-SPDeltaCertEscalate.ps1 Every 4 hours (business hours) Catch stale certifications between daily runs
Invoke-SPWeeklyDigest.ps1 Monday at 07:00 Weekly governance summary for leadership

Windows Task Scheduler

Create a scheduled task using PowerShell:

# Daily orchestrator at 6:00 AM
$action = New-ScheduledTaskAction -Execute "powershell.exe" `
    -Argument "-NoProfile -ExecutionPolicy Bypass -File `"C:\GovernanceToolkit\Scripts\Invoke-SPDailyOrchestrator.ps1`" -SourceId 'src-ad-001'"
$trigger = New-ScheduledTaskTrigger -Daily -At '06:00'
$settings = New-ScheduledTaskSettingsSet -StartWhenAvailable -DontStopOnIdleEnd
Register-ScheduledTask -TaskName "SailPoint-DailyOrchestrator" `
    -Action $action -Trigger $trigger -Settings $settings `
    -User "DOMAIN\ServiceAccount" -Password "***"

# Escalation every 4 hours during business hours (8 AM - 6 PM)
$action = New-ScheduledTaskAction -Execute "powershell.exe" `
    -Argument "-NoProfile -ExecutionPolicy Bypass -File `"C:\GovernanceToolkit\Scripts\Invoke-SPDeltaCertEscalate.ps1`" -StaleHours 24"
$trigger = New-ScheduledTaskTrigger -Daily -At '08:00'
$repetition = New-TimeSpan -Hours 4
$duration = New-TimeSpan -Hours 10
$trigger.Repetition.Interval = $repetition
$trigger.Repetition.Duration = $duration
Register-ScheduledTask -TaskName "SailPoint-Escalation" `
    -Action $action -Trigger $trigger -Settings $settings `
    -User "DOMAIN\ServiceAccount" -Password "***"

Identity Exclusion Filters

Service accounts, admin accounts, and other non-human identities can be excluded from delta cert campaigns even if they receive AD group grants:

Setting Type Description
ExcludeLifecycleStates string[] Identity lifecycle states to exclude. Default: terminated, inactive, leaver, prehire. Customize to add states like dormant.
ExcludeDisplayNamePatterns string[] Regex patterns matched against identity displayName. Examples: ^SVC-, ^ADM-, Service Account.
ExcludeIdentityIds string[] Explicit identity IDs to always skip regardless of other criteria.

JSONL Audit Trail

Every delta cert run, escalation, and orchestrator execution appends a structured JSONL event to the output directory for compliance evidence and troubleshooting:

File Source Key Fields
deltacert-audit.jsonl Invoke-SPDeltaCertRun Timestamp, CorrelationID, SourceIds, HoursBack, GrantEventsFound, CampaignsCreated, CampaignIds, Reason
deltacert-escalation.jsonl Invoke-SPDeltaCertEscalate.ps1 Timestamp, CorrelationID, StaleCertsFound, Escalated, Skipped, StaleHours, MaxEscalationLevels
orchestrator-audit.jsonl Invoke-SPDailyOrchestrator.ps1 Timestamp, CorrelationID, Steps (per-step status/detail/duration), ExitCode, DurationSeconds

Each line is valid JSON parseable by ConvertFrom-Json. No-change runs (Reason=NoChanges) are also logged for a complete operational history.
