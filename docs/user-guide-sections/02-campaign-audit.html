Campaign Audit

The Campaign Audit workflow produces post-campaign compliance reports with reviewer accountability, decision breakdowns, remediation proof, risk indicators, and leadership rollups. It queries completed or active ISC certification campaigns, retrieves all certifications and review items, and generates per-campaign HTML reports plus a combined summary and JSONL audit trail.

Campaign Audit Overview

Each audit run produces three types of output:

Output Format Purpose
Per-campaign report HTML + TXT Detailed audit of a single campaign: executive dashboard, decision breakdown, reviewer metrics, remediation proof
Combined report HTML Multi-campaign summary covering all campaigns in a single run
Audit trail JSONL Machine-readable compliance evidence with 18 mandatory fields per decision

The per-campaign HTML report opens with an Executive Summary Dashboard containing a status badge, decision breakdown donut chart (SVG), remediation completion bar, risk scorecard, and reviewer response time summary. Below the dashboard, seven detailed sections follow:

  1. Campaign Summary -- name, status, dates, duration, certification count
  2. Reviewer Accountability -- primary certifiers and reassignments with sign-off proof
  3. Reviewer Performance -- time-to-decision metrics per reviewer, color-coded by response time
  4. Decision Summary -- approved, revoked, and pending items with identity and entitlement detail
  5. Campaign Reports -- Campaign Status Report and Certification Signoff Report from ISC
  6. Remediation and Reassignment Proof -- item-level completion status and reassignment chain
  7. Audit Metadata -- correlation ID, generation timestamp, and filters applied

Output directory structure:

Audit\
    <CampaignName>\
        campaign-audit-<CampaignName>-<timestamp>.html    # Per-campaign HTML report
        campaign-audit-<CampaignName>-<timestamp>.txt     # Per-campaign text summary
    campaign-audit-combined-<timestamp>.html               # Combined multi-campaign HTML
    audit-<timestamp>.jsonl                                # JSONL audit trail
    leadership\                                            # (if -IncludeLeadershipRollup)
        executive-summary.html
        <LevelLabel>-<LeaderName>-<timestamp>.html

CLI Reference: Invoke-SPCampaignAudit.ps1

The primary audit script. At least one campaign filter is required -- without a filter the script exits with code 2.

.\Scripts\Invoke-SPCampaignAudit.ps1 [-Status <string[]>] [-CampaignName <string>]
    [-CampaignNameStartsWith <string>] [-CampaignNameContains <string>]
    [-DaysBack <int>] [-IdentityEventDays <int>] [-DetailLevel <string>]
    [-IncludeLeadershipRollup] [-LeadershipDepth <int>] [-LeadershipStartLevel <int>]
    [-OutputPath <string>] [-OutputMode <string>] [-Token <string>]
    [-CampaignReportCsvPath <string>] [-WhatIf] [-Help]

Campaign Filter Parameters

At least one of these is required. They can be combined (e.g., -Status COMPLETED -CampaignNameContains 'quarterly').

Parameter Type Description
-CampaignName string Exact name match (case-insensitive). Maps to ISC filter name eq "...".
-CampaignNameStartsWith string Prefix match. Maps to ISC filter name sw "...".
-CampaignNameContains string Substring match anywhere in the name. Maps to ISC filter name co "...". Recommended for keyword-based searching.
-Status string[] One or more campaign statuses. Valid values: STAGED, ACTIVE, COMPLETING, COMPLETED.

Data Control Parameters

Parameter Type Default Description
-DaysBack int 30 Only include campaigns created within the last N days. Overridden by Audit.DefaultDaysBack in settings.json.
-IdentityEventDays int 2 Days before campaign end date to search for identity lifecycle events for revoked identities.
-CampaignReportCsvPath string -- Path to a locally exported campaign report CSV. When provided, skips live campaign-report API calls.

Output Parameters

Parameter Type Default Description
-OutputPath string .\Audit Directory for audit output files. Created if absent. Overrides Audit.OutputPath in settings.json.
-OutputMode string Console Console summary format. Valid values: Console, JSON, Both.
-DetailLevel string Verbose Identity-level detail in HTML reports. Valid values: Summary, Detailed, Verbose.

Leadership Rollup Parameters

Parameter Type Default Description
-IncludeLeadershipRollup switch off Generate leadership rollup reports. Requires SP.DeltaCert module. Also configurable via Audit.IncludeLeadershipRollup in settings.json.
-LeadershipDepth int 3 Maximum org levels to walk above reviewed identities. 3 = identity, manager, director, VP.
-LeadershipStartLevel int -1 Highest level from which to begin generating per-level reports. -1 = auto-detect (highest level found).

Authentication Parameters

Parameter Type Default Description
-Token string -- Browser JWT bearer token from the ISC admin console. Bypasses OAuth entirely. ~12 minute expiry.
-TokenExpiryMinutes int 10 Minutes until the browser token is considered expired.
-ConfigPath string auto Path to settings.json. Defaults to auto-resolved path relative to the Scripts directory.

Exit Codes

Code Meaning
0 Audit completed successfully
1 No campaigns matched the filter criteria
2 Parameter error (missing required filter or invalid combination)
3 Authentication error (failed to acquire token)
4 Configuration error (settings.json missing, invalid, or first-run placeholders)

Leadership Rollup Reports

Leadership rollups aggregate campaign decisions up the organizational hierarchy, producing per-level reports for VPs, directors, and managers. Enable with -IncludeLeadershipRollup or set Audit.IncludeLeadershipRollup = true in settings.json.

How It Works

  1. The toolkit collects all unique identity IDs from campaign decisions
  2. Build-SPOrgTree walks each identity's ISC manager chain upward to -LeadershipDepth levels
  3. Decisions are grouped by org level using Group-SPAuditByLeadership
  4. Per-level HTML reports are generated for each leader at each level

Org Level Labels

The toolkit assigns labels based on the absolute distance from individual contributors (level 0):

Level Label Typical Role
0 Individual Contributors End users whose access was reviewed
1 Managers Direct managers who reviewed certifications
2 Directors Second-level leaders overseeing managers
3 Vice Presidents Third-level leaders overseeing directors
4 Senior Vice Presidents Fourth-level leaders
5 Executive Leadership C-suite or equivalent

Depth Control

The -LeadershipDepth parameter controls how far up the org tree to walk. The -LeadershipStartLevel parameter controls where report generation begins (-1 = auto-detect, starting from the highest level found).

# Walk 3 levels: identity -> manager -> director -> VP
.\Scripts\Invoke-SPCampaignAudit.ps1 -Status COMPLETED -DaysBack 30 -IncludeLeadershipRollup

# Walk only 2 levels: identity -> manager -> director (no VP reports)
.\Scripts\Invoke-SPCampaignAudit.ps1 -Status COMPLETED -IncludeLeadershipRollup -LeadershipDepth 2

# Walk 4 levels for a large org
.\Scripts\Invoke-SPCampaignAudit.ps1 -Status COMPLETED -IncludeLeadershipRollup -LeadershipDepth 4

Executive Summary Report

The executive summary (leadership/executive-summary.html) provides a high-level view across all directors. It includes overall approval/revocation rates, an SVG donut chart, and a per-director summary table sorted by completion percentage ascending (worst-performing first). Completion cells are color-coded: green for >= 95%, orange for 80-95%, red for < 80%.

Per-Leader Reports

Each leader at each level gets an individual report with:

  • Level-appropriate header (e.g., "VP Report: Alice Johnson")
  • Summary cards showing total items, approved, revoked, and pending counts
  • Subordinate table listing each direct report's decision statistics
  • Navigation links up to parent report and down to child reports
  • At the lowest generated level: full identity decision detail

Detail Levels

The -DetailLevel parameter controls how much identity-level information appears in the HTML reports. All three levels include the executive dashboard, reviewer accountability, and campaign metadata. The difference is in the decision detail tables.

Summary -- Counts and percentages only

Shows aggregate statistics: total items, approval rate, revocation rate, completion percentage, and reviewer count. No per-identity or per-entitlement detail. Best for executive-level distribution where readers need the headline numbers only.

.\Scripts\Invoke-SPCampaignAudit.ps1 -Status COMPLETED -DetailLevel Summary
Detailed -- Identity names and decisions

Includes per-identity rows with name, account identifier, access name, decision, and reviewer. Omits lifecycle events, remediation timestamps, and justification text. Good for manager-level review where the focus is on who-decided-what.

.\Scripts\Invoke-SPCampaignAudit.ps1 -Status COMPLETED -DetailLevel Detailed
Verbose -- Full compliance evidence (default)

Everything in Detailed plus: justification comments, remediation status and dates, identity lifecycle events, risk flags, and the full reassignment chain. This is the default and the level required for SOX/SOC2 compliance evidence packages.

.\Scripts\Invoke-SPCampaignAudit.ps1 -Status COMPLETED -DetailLevel Verbose

Compliance Features

18 Mandatory Compliance Fields

Every access review decision is emitted as a DecisionRecorded event in the JSONL audit trail with exactly 18 fields. This structure supports SOX, SOC2, and NIST audit requirements:

Field Description
Action Always DecisionRecorded
IdentityName Display name of the identity whose access was reviewed
IdentityId ISC identity ID
AccountId ISC account ID linked to the identity
ApplicationSource ISC source name (e.g., "Active Directory - Corp")
EntitlementName Name of the entitlement or access profile reviewed
AccessType Type of access (entitlement, access profile, role)
ReviewerName Name of the reviewer who made the decision
ReviewerEmail Email address of the reviewer
Decision APPROVE, REVOKE, or pending (no decision recorded)
DecisionDateTime ISO 8601 timestamp of the decision
Justification Reviewer's comment or justification text
CampaignName Name of the certification campaign
CampaignStart Campaign start date
CampaignDueDate Campaign deadline
CampaignCompletion Campaign completion date
RemediationStatus Provisioned (completed), Pending, or N/A (non-revoke)
RemediationDate Date the revocation was provisioned (if applicable)
Note

Two additional fields (ReassignmentChain and SystemTimestamp) are also included in the JSONL event, bringing the total to 20 fields per event. The 18 above are the mandatory compliance fields referenced in the audit report headers.

Anti-Rubber-Stamping Detection

The Measure-SPAuditRubberStampRisk function performs four SOX/SOC2 red-flag checks on reviewer behavior, producing a per-reviewer risk severity (None, Low, Medium, High):

Check What It Detects Threshold
Approval-only rate Reviewer approved 100% of items without a single revocation 100% approval across > 10 items
Decision velocity Decisions made faster than humanly possible for the item count > 50 items decided in < 60 seconds
Bulk decision clusters Consecutive identical decisions within a narrow time window > 5 identical decisions within 30 seconds
Response latency First decision made suspiciously soon after campaign assignment < 1 minute after assignment with > 5 items

Severity is calculated as: High = 2+ flags; Medium = 1 flag (velocity or approval-only); Low = 1 flag (other type); None = 0 flags.

Risk Indicators

The Get-SPAuditRiskFlags function adds risk flags to individual access review decisions. Each decision item can receive zero or more of the following flags:

Flag Color Trigger
STALE Orange Last login > StaleAccessDays ago (default 90)
PRIVILEGED Red Entitlement name matches PrivilegedPatterns (Admin, Root, DBA, Domain Admins)
ORPHAN Red Identity has no manager assigned in ISC
TERMINATED Red Identity lifecycle state is terminated
SVC-ACCOUNT Gray Identity name matches ServiceAccountPatterns (^SVC-, ^svc-)

Risk indicator thresholds are configurable in settings.json under Audit.RiskIndicators:

"Audit": {
    "RiskIndicators": {
        "StaleAccessDays": 90,
        "PrivilegedPatterns": ["Admin", "Root", "DBA", "Domain Admins"],
        "ServiceAccountPatterns": ["^SVC-", "^svc-"]
    }
}

Campaign Search

Invoke-SPCampaignSearch.ps1 is a unified campaign search and analysis tool. It combines keyword/type/status/date filtering with five analysis modes for deeper investigation.

.\Scripts\Invoke-SPCampaignSearch.ps1 [-Keyword <string>] [-Type <string>]
    [-Status <string[]>] [-DaysBack <int>] [-CreatedAfter <DateTime>]
    [-CreatedBefore <DateTime>] [-ShowDeadlines] [-ShowMetrics]
    [-ReviewerIdentityId <string>] [-IdentityId <string>]
    [-SourceCoverage] [-CompareIds <string[]>]
    [-OutputMode <string>] [-OutputPath <string>]
    [-Token <string>] [-Help]

Search Parameters

Parameter Type Default Description
-Keyword string -- Substring search against campaign names. Uses ISC co (contains) filter.
-Type string -- Campaign type. Valid values: MANAGER, SOURCE_OWNER, SEARCH, ROLE_COMPOSITION.
-Status string[] COMPLETED, ACTIVE One or more statuses. Also accepts: STAGED, ACTIVATING, COMPLETING, ERROR.
-DaysBack int 90 Look-back window. Ignored when -CreatedAfter or -CreatedBefore is specified.
-CreatedAfter DateTime -- Lower bound for campaign creation date. Takes precedence over -DaysBack.
-CreatedBefore DateTime -- Upper bound for campaign creation date. Takes precedence over -DaysBack.
-OutputMode string Console Output format. Valid values: Console, JSON, CSV, HTML.
-OutputPath string .\SearchResults Directory for CSV/HTML output files. Created if absent.

Analysis Modes

Only one analysis mode can be active at a time. When none is specified, the default is a standard campaign search with optional deadline and metrics enrichment.

Deadline Urgency (-ShowDeadlines)

Adds an urgency classification to each campaign result based on its deadline and status:

Classification Criteria
Overdue Deadline has passed AND campaign is still ACTIVE
Critical Deadline within 24 hours AND ACTIVE
Warning Deadline within 72 hours AND ACTIVE
OnTrack Deadline more than 72 hours away AND ACTIVE
Completed Campaign status is COMPLETED
NoDeadline No deadline set on the campaign 
.\Scripts\Invoke-SPCampaignSearch.ps1 -Status ACTIVE -ShowDeadlines
Campaign Metrics (-ShowMetrics)

Retrieves per-campaign KPIs including approval rate, completion rate, reviewer count, and response time statistics (average, min, max, median hours). Also identifies the fastest and slowest reviewers and calculates items-per-reviewer distribution.

.\Scripts\Invoke-SPCampaignSearch.ps1 -Status COMPLETED -DaysBack 90 -ShowMetrics -OutputMode CSV
Reviewer Workload (-ReviewerIdentityId)

Finds all campaigns and certifications assigned to a specific reviewer. Returns per-campaign workload counts: items assigned, decided, and pending.

.\Scripts\Invoke-SPCampaignSearch.ps1 -ReviewerIdentityId 'id-mgr-001' -Status ACTIVE
Identity Decision History (-IdentityId)

Shows all access review decisions about a specific identity across all matching campaigns. Returns per-campaign decision lists with access name, decision, reviewer, and date.

.\Scripts\Invoke-SPCampaignSearch.ps1 -IdentityId 'id-001' -Status COMPLETED -DaysBack 365
Source Coverage (-SourceCoverage)

Analyzes which ISC sources have been included in certification campaigns and which have not. Returns covered sources, uncovered sources, and a coverage rate percentage.

.\Scripts\Invoke-SPCampaignSearch.ps1 -SourceCoverage -DaysBack 365
Campaign Comparison (-CompareIds)

Side-by-side metric comparison of two or more campaigns by ID. Produces a comparison table with approval rates, revocation rates, reviewer counts, and response times.

.\Scripts\Invoke-SPCampaignSearch.ps1 -CompareIds 'camp-001','camp-002' -OutputMode HTML

Report Distribution

Invoke-SPReportDistribution.ps1 generates leadership reports with optional SMTP email delivery. It combines campaign audit, leadership rollup, org tree building, band classification, and per-band filtering into a single CLI workflow. Default behavior is generate-only.

.\Scripts\Invoke-SPReportDistribution.ps1 -Status <string[]> [-DaysBack <int>]
    [-LeadershipDepth <int>] [-TargetBands <string[]>] [-DetailLevel <string>]
    [-OrgSupplementPath <string>] [-PreviewOnly] [-SendReports]
    [-OutputPath <string>] [-OutputMode <string>] [-Token <string>] [-Help]

Parameters

Parameter Type Default Description
-Status string[] Mandatory Filter campaigns by status. Valid values: STAGED, ACTIVE, COMPLETING, COMPLETED.
-DaysBack int 30 Only include campaigns created within the last N days.
-LeadershipDepth int 4 Maximum org levels to walk above reviewed identities.
-TargetBands string[] all Band letters to include (e.g., @('B','C')). Omit to include all bands.
-DetailLevel string Verbose Identity-level detail in reports. Valid values: Summary, Detailed, Verbose.
-OrgSupplementPath string from config Path to an org chart supplement CSV to fill gaps in ISC manager chain data.
-PreviewOnly switch off Show distribution plan without generating reports or sending email. Exits after preview.
-SendReports switch off Send generated reports to leaders via SMTP. Requires Audit.Smtp config.

Workflow

  1. Query campaigns matching the status and date filters
  2. Collect all certifications, review items, and decisions per campaign
  3. Build the org tree via Build-SPOrgTree
  4. If an org supplement CSV is configured: merge it with the API-derived org tree
  5. Assign A-E band classifications via Resolve-SPIdentityBand
  6. Group decisions by leadership level and band
  7. Generate per-band filtered HTML reports via Export-SPLeadershipBandHtml
  8. If -SendReports: match reports to leader emails and send via SMTP
# Preview the distribution plan first
.\Scripts\Invoke-SPReportDistribution.ps1 -Status COMPLETED -DaysBack 30 -PreviewOnly

# Generate reports for Band B and C leaders only
.\Scripts\Invoke-SPReportDistribution.ps1 -Status COMPLETED -DaysBack 30 -TargetBands B,C

# Full distribution with SMTP delivery
.\Scripts\Invoke-SPReportDistribution.ps1 -Status COMPLETED -DaysBack 30 -SendReports

# Use org chart supplement to fill gaps
.\Scripts\Invoke-SPReportDistribution.ps1 -Status COMPLETED -OrgSupplementPath '.\Config\org-chart-supplement.csv'

Band Classification

The toolkit assigns A-E band letters to leaders in the org tree for report filtering and distribution. Band assignment uses a three-source priority system:

Priority Source How It Works
1 (highest) Org Chart Supplement CSV Explicit band column in the supplement CSV, keyed by email address
2 ISC Identity Attribute Reads the jobLevel attribute (or custom attribute from Leadership.ISCBandAttribute). If the value is already a valid band letter, uses it directly.
3 (fallback) Auto-detect from Tree Depth Uses BandMapping to map org level to band letter. Default: 0=E, 1=D, 2=C, 3=B, 4=A.

Band Definitions

Band Typical Level Description
A President / C-Suite Top-level executives
B VP / SVP Vice presidents and senior vice presidents
C Director Second-level leaders
D Manager First-level people managers
E Individual Contributor End users

Org Chart Supplement CSV

To override or fill gaps in ISC manager chain data, provide a CSV with the following columns:

identityEmail,managerEmail,level,title,band
alice@example.com,bob@example.com,3,Vice President of Engineering,B
bob@example.com,,4,CTO,A
carol@example.com,alice@example.com,2,Director of Security,C

The supplement is configured in settings.json:

"Leadership": {
    "OrgChartSupplementPath": ".\\Config\\org-chart-supplement.csv",
    "UseSupplementForReports": true,
    "DefaultBandMapping": { "0": "E", "1": "D", "2": "C", "3": "B", "4": "A" },
    "ISCBandAttribute": "jobLevel"
}

Example Workflows

Quarterly Compliance Audit

Run at the end of each quarter to generate a comprehensive audit package for all completed campaigns within the quarter.

# Step 1: Dry-run to review matching campaigns
.\Scripts\Invoke-SPCampaignAudit.ps1 -Status COMPLETED -DaysBack 90 -WhatIf

# Step 2: Generate full audit with leadership rollup
.\Scripts\Invoke-SPCampaignAudit.ps1 -Status COMPLETED -DaysBack 90 \
    -IncludeLeadershipRollup -LeadershipDepth 3

# Step 3: Distribute leadership reports to Band B and C leaders
.\Scripts\Invoke-SPReportDistribution.ps1 -Status COMPLETED -DaysBack 90 \
    -TargetBands B,C -PreviewOnly

# Step 4: After reviewing preview, send reports
.\Scripts\Invoke-SPReportDistribution.ps1 -Status COMPLETED -DaysBack 90 \
    -TargetBands B,C -SendReports
Annual Compliance Review

Year-end review covering all campaigns with source coverage analysis to identify gaps.

# Step 1: Source coverage -- which apps were audited, which were not
.\Scripts\Invoke-SPCampaignSearch.ps1 -SourceCoverage -DaysBack 365

# Step 2: Full audit with verbose detail for the archive
.\Scripts\Invoke-SPCampaignAudit.ps1 -Status COMPLETED -DaysBack 365 \
    -IncludeLeadershipRollup -LeadershipDepth 4

# Step 3: Generate leadership reports for all bands
.\Scripts\Invoke-SPReportDistribution.ps1 -Status COMPLETED -DaysBack 365 \
    -LeadershipDepth 4
Ad-Hoc Investigation

Investigate a specific campaign or identity for an internal audit or incident response.

# Investigate a single campaign by name
.\Scripts\Invoke-SPCampaignAudit.ps1 -CampaignName 'Privileged Access Review 2026-Q1'

# Trace all decisions about a specific identity
.\Scripts\Invoke-SPCampaignSearch.ps1 -IdentityId 'abc123def' -DaysBack 365

# Check a reviewer's workload across active campaigns
.\Scripts\Invoke-SPCampaignSearch.ps1 -ReviewerIdentityId 'mgr-456' -Status ACTIVE

# Compare two campaigns side by side
.\Scripts\Invoke-SPCampaignSearch.ps1 -CompareIds 'camp-q1','camp-q2' -OutputMode HTML
Active Campaign Monitoring

Monitor in-flight campaigns for deadline risks and reviewer bottlenecks.

# Show all active campaigns with deadline urgency
.\Scripts\Invoke-SPCampaignSearch.ps1 -Status ACTIVE -ShowDeadlines

# Show active campaigns with full metrics
.\Scripts\Invoke-SPCampaignSearch.ps1 -Status ACTIVE -ShowMetrics

# Export active campaign data to CSV for executive review
.\Scripts\Invoke-SPCampaignSearch.ps1 -Status ACTIVE -ShowDeadlines -ShowMetrics -OutputMode CSV
