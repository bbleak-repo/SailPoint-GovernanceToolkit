## Approach

W-07 does NOT re-open the report in a browser; W-06's Playwright captures
already proved the rendered behaviour. This round validates the
**underlying HTML structure** emitted by `Build-SPCampaignAuditHtml`, so
that any future template regression that drops a section header or breaks
an `open` attribute is caught even without a visual diff.

For each check the harness uses a precise regex against the report HTML
(loaded once with `Get-Content -Raw`). Multi-line patterns use
`(?s)Singleline` mode so `.*?` can cross newlines. Where a section uses
nested `<table>` elements (Reviewer Response Time has a progress-bar
table per row), the harness bounds the search by a section-ending sentinel
(e.g. `Campaign average:`) rather than by `</table>`, which would stop
inside the first nested progress bar.

## Bugs fixed during harness development

Two harness regex bugs caught + fixed during iteration -- no production code
bugs found:

1. **WR-07-01** initially failed because the regex
   `background:\s*#339933[^>]*>\s*COMPLETED` expected the text "COMPLETED"
   to follow the opening `<td ...>` directly, but the template wraps it
   in a `<span style="color:#fff; ...">COMPLETED</span>`. Adjusted to
   `(?s)background:\s*#339933[^>]*>\s*<span[^>]*>\s*COMPLETED\s*</span>`.

2. **WR-07-05** initially failed because the regex `Reviewer Response Time.*?</table>`
   stopped at the very first `</table>` -- which closes the *nested*
   progress-bar table for Diana Brown -- leaving only one reviewer
   captured. Switched the bound from `</table>` to the section's
   trailing `Campaign average:` line, which is outside any nested table.
   Block now correctly captures all four reviewer names.

No production bugs found in the HTML template -- all 15 backlog checks
pass against the report Build-SPCampaignAuditHtml emits as-is.
